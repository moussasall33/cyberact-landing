Platform core

Central risk register

A unified register consolidates risks from every module. Three risk states are tracked at each step: from inherent risk to residual risk, via adjusted risk after existing controls. The G×V heatmap updates in real time.

State 1
Inherent risk
Before any control, based on EBIOS RM scenarios.
State 2
Adjusted risk
After accounting for existing security controls.
State 3
Residual risk
After applying the validated treatment plan.
ISP EBIOS RM scenarios → inherent risks
Audit Identified non-conformities → residual risks
TPRM Vendor gaps → residual risks
Roadmap Closed treatment plans → residual recalculation

Cross-cutting capabilities

Risk-driven, everywhere

Risk ↔ compliance loop

Every requirement mapped to a real risk. Every audit non-conformity automatically feeds the register. 3 states tracked: inherent → adjusted → residual (ISO 27005).

4 input modes everywhere

Manual · file import · AI generates · AI restructures, plus the catalogue mode where relevant. No option imposed, humans validate everything.

Multi-tenant & multi-subsidiary

Strong isolation via Postgres Row-Level Security. Group policies → subsidiaries with consolidated exports and local annexes.

AI proposes, humans decide

Sovereign on-prem AI or external API, multi-provider orchestration with automatic fallback. A deterministic rule engine proposes the GO / GOC / NO-GO verdict. The CISO decides.

Security by design

AES-256-GCM, MFA TOTP + WebAuthn/FIDO2 passkeys, HSTS, strict CSP. Architecture designed around 18 security-by-design principles. OWASP LLM Top 10 integrated.

Audit logs ISO 27001 A.5.34

100% of actions traced (timestamp, IP, user, action). SIEM-compatible syslog export, advanced filters, anti-DoS rate-limiting. NIS 2 art. 21.2.h.
